## 判定の基本線（2026-11-16）

YouTube公式 IFrame Player API の `seekTo(seconds,allowSeekAhead)` は時間指定での移動。停止中なら再生停止状態を維持するが、未バッファ区間では指定時刻の直前のキーフレームへ移ることがある。**デコードされた隣の映像コマを1つ表示する独立APIは提供されていない。**

- 誤った推論：`+1/30秒` を `seekTo()` に渡した＝30fps動画の次のコマが正確に表示された。
- 本試験で観測可能なのは、IFrame APIの報告時刻（数値）とiPhoneの画面上での移動（本人目視）。API時刻の変化を映像の正確なコマ送りPASSとしない。
- 別の `<video>` に公式YouTubeの再生URLを抽出して渡す方法は使用しない。非公式API、動画ストリームURL抽出、iframe内部DOM/画素の読み取り、動画ダウンロード、キャッシュやサーバー中継は実装しない。

公式根拠:
- https://developers.google.com/youtube/iframe_api_reference
- https://developers.google.com/youtube/terms/developer-policies/
- https://support.google.com/youtube/answer/56100/download-videos-that-you-ve-uploaded

## 実装する安全な最小試験

1. B0でOAuth承認された本人の限定公開動画一覧の各行に、**「公式プレイヤーで細かい時刻移動を試す（検証）」**を追加する。
2. このボタンを本人がタップした場合のみ、YouTube公式の `https://www.youtube.com/iframe_api` を遅延読み込みし、同一ページ内の公式プレイヤーへ選択した動画を表示する。URL/履歴/保存領域へ動画IDを転記しない（ただし再生に伴うYouTubeへの通信は行われる）。
3. 公式プレイヤーで再生→「一時停止」→「±1秒」/「±1/30秒（時刻移動）」を試す。停止状態でない場合はシークを受け付けない。
4. `seekTo` の約1秒後に `getCurrentTime()` を読み、指定時刻から大きく外れないか診断する。**結果文言は必ず「表示フレームの変化は未証明」**とする。
5. 別動画を選べる。B0の「一覧・接続を消去」でプレイヤーも破棄する。OAuthの追加スコープ・PC常時稼働・動画の外部アップロードは不要。

B0の既存OAuth一覧取得・モックデータの動作は変更しない。Mock一覧自体には再生ボタンを表示しない。既存B1合成動画のステップページも変更しない。

## Owner iPhone Safariのテスト手順と判定

1. B0ページをSafariで開き、通常どおりGoogle認証して自分の限定公開動画一覧を表示する。
2. **動きがはっきりしている本人のSF6動画**を一件選び、新しい検証ボタンをタップする。
3. 公式YouTubeプレイヤーが表示されたか確認。埋め込み不可エラーなら原因候補を記録し、無理に取得しない。
4. 動きのある場面を再生→一時停止し、`+1/30秒` 3回、`-1/30秒` 3回。各タップで実際の絵がどう動いたか、停止状態のままかを見る。
5. 判定を「(A) ほぼ1コマずつ動く」「(B) 時刻だけ動く・同じ映像が続く」「(C) 複数コマ飛ぶ／不安定」「(D) 埋め込み再生不可／エラー」に分類する。Aでも**動画形式や未バッファ部分まで正確に保証したわけではない**。
